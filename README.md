# ランク人狼Bot

13人/9人・クロストーク/ターン制・ボタンUI・レーティング付きの Discord 人狼ゲーム Bot です。
役職の配布から昼の議論・投票、夜の役職行動、シーズン制のレート/ランクまでを
すべて自動で進行します。

- 現在のバージョン: **v0.40**（`config.py` の `BOT_VERSION` が正。更新時は `CHANGELOG.md` とここも揃える）
- 詳細仕様: **[SPEC.md](SPEC.md)**

## 主な機能

- **4変種を実装**: 13人クロストーク / 13人ターン / 9人クロストーク / 9人ターン（13人ターン制は実装済み・未公開）
- 13人配役は人狼3 / 狂人1 / 占い師1 / 霊媒師1 / 狩人1 / 村人6、9人配役は人狼2 / 狂人1 / 占い師1 / 霊媒師1 / 狩人1 / 村人3
- すべてボタン/セレクトUIで操作（スラッシュコマンドは管理用のみ）
- 夜の役職行動はDM。襲撃は夜の間は変更可、占い・護衛は実行確認後に確定し変更不可。**狩人は護衛放棄不可**で、自分・前夜と同じ人は護衛できない
- 占い結果は確定と同時にDMへ届く（エフェメラル表示とは別に通常DMでも残る）
- ゲーム開始直後は時間切れでは進まず、**参加者全員が「役職を確認した」を押すと議論開始**（一度押すと取り消せない）
- クロストークは**議論中から仮投票できる**（投票フェーズまでは何度でも入れ替え可）。ターン制は仮投票なし
- クロストークの議論時間は、13人村が初日8分・毎日1分短縮・下限3分、9人村が初日7分・毎日1分短縮・下限2分
- ターン制は初日50秒+80秒の2巡、2日目以降90秒の1巡。初日はランダム、以後は前夜の襲撃死者の次（護衛成功なら襲撃対象、どちらもなければランダム）から時計回りに話す。護衛成功時の開始席は公開情報だが、朝の文面は常に「平和な朝」のみ。本人のパスと村全体の30秒割り込み（13人は1日2回、9人は1回）に対応し、`#昼` は書き込み不可でVCだけを使う
- ターン制のCOは初日2巡目と2日目以降の唯一の巡に、`#昼` の「COを宣言」で名前だけを公開する。当日1回だけ生存・VC復帰済み参加者が押せ、役職・理由の詳細や偽COを含む発言はVCで行う
- 夜は時間切れでは明けず、**`#昼` のパネルで生存者全員が「朝を迎える」を押すと朝**になる（宣言人数は夜の間は誰にも見せず、目安時間が切れたときに全員へ同時に公開。GMのみGMメニューの「朝」で強制可。ただし未護衛の生存狩人がいれば強制不可）
- 人狼どうしのやり取りは**夜の制限時間で終了**（会話の中継も襲撃先の変更通知も止まる。襲撃先の選択自体は夜明けまで可能だが他の狼には伝わらない）
- 投票と破壊的なGM操作は確認してから確定（誤操作防止）
- ゲーム中のGM状況・操作は `#昼` の末尾、受付操作は `#参加受付` の末尾に維持
- 常設卓は13人クロストークの「総合」とローカル固定卓（実運用では「ねいとくん村」）だけ。初心者・中級者・上級者・総合-9クロストーク・総合-9ターンは廃止し、13人ターン制は引き続き未公開
- `#統計` は既存の `#総合` の直下に1つだけ配置
- `#統計` の成績・履歴・勝率は稼働中の3変種で切り替え、レート順位は対応する13人/9人ラダーで表示（13人ターン制の履歴定義はDBに保持）
- ローカル固定卓は`.env`だけで追加可能。「ねいとくん村」はカテゴリ・`#参加受付`・VCの平常時権限をDiscordの手動設定のまま保持し、他のローカル卓は`sync_permissions=false`を明示した場合だけ同じ手動モードになる
- 起動時には既存チャンネル・カテゴリを並び替えず、保存済みIDと卓名から同じ構成を再利用
- `#統計` から不具合・分かりにくさ・改善要望を報告し、ゲーム状況とともにSQLiteへ保存
- GMまたは仮GM向けの `GM/#村作成` から名前村と募集を同時作成。募集カードはその村の `#参加受付` に置き、参加・取消・同村拒否確認・ゲーム開始を1か所で完結（独立した `#募集` は作らない）
- GM名前村は「総合」と同じ公開観戦型。カテゴリ・VC・`#昼`・`#霊界`を未参加者にも公開し、VCにも接続可能（生存参加者だけはゲーム中の`#霊界`を閲覧不可）。ゲーム中の観戦者は聞くだけで、VC発言とVC内チャットをBotが禁止し、参加者だけを進行に合わせて発言制御する
- 名前村の参加ボタンは参加意思・定員・ランク条件・同村拒否を管理するために使い、閲覧権限は変更しない。参加取消後も観戦者としてVCやゲーム中チャンネルを利用できる
- 作成時と受付中に13人クロストーク / 9人クロストーク / 9人ターン制を選択・変更可能。定員、補欠、自動繰り上げ、参加者単位の15分前DMも選択中の形式へ追従
- 募集条件は「制限なし / 初心者 / 中級者 / 上級者」から簡単に選べ、必要な場合はランクを個別指定可能。初心者にはランク未設定者も含む
- `#参加受付` の `🔔通知` を押すと `@通知` ロールを自分で付与・解除でき、新しい募集が作成された時だけ通知を受け取れる
- 正常終了した総合・ローカル固定卓・GM名前村の全ゲームを統計・ランキング・レート・ランクへ反映。13人村・9人クロストーク・9人ターン制は別ラダーで管理
- `#統計` の本人専用UIで最大50人の同村拒否を管理し、追加候補・登録済み一覧は25人ずつページ切替。既存の `開発/#運営` で被拒否数・9人均衡・受付中GM・募集を管理。Botは `開発` カテゴリも `#運営` も新規作成せず、欠落時は運営UI・通知だけを無効化してゲーム本体を継続。チャンネル閲覧者はDiscord上の手動権限設定で管理し、運営操作はAdministrator・所有者・設定運営ロールに限定
- `#統計` の「全体データ」で卓別の勝敗・日数・平和・処刑・初夜噛み・生存狼推移・時間帯・GMを表示。プレイヤー指標は試合時の相対ランク別に切替
- 占い・護衛・死亡日/死因・試合時ランク・GMを導入後の各試合へ保存し、個人統計にシーズン役職勝率・連勝/連敗・初夜襲撃・推薦数を追加
- サーバーミュートによる自動発言制御（昼/夜/投票/弁明/遺言）
- 13人村 `l13` / 9人クロストーク `l9_cross` / 9人ターン制 `l9_turn` の3ラダー。変種別固定プール + 卓帯補正 + 活躍ボーナス + エメラルドを含む相対ランク9段階 + 共通シーズン境界
- 終了後、霊媒師・初日処刑者・初夜襲撃死者が匿名で参加者へレート+1を贈る推薦
- 終了時に**全役職の行動・投票・死亡を発生順にまとめた進行ログ**を `#昼` へ掲示（拒否された操作も残るため二重実行の有無をその場で確認できる）
- 総合・ローカル固定卓（手動権限卓を含む）・GM名前村で終了した `#昼` / `#霊界` は、すべて**公開ログカテゴリへ試合番号付きで退避**（`04-昼`。書き込み不可・最大50試合ぶんで、上限に達すると古い順に40試合ぶんまで整理）
- Bot再起動をまたいでゲームを途中再開（状態をSQLiteへ常時保存）
- シーン切替の効果音（任意・後述の音声ライブラリが必要）

## 動作要件

- Python 3.14（3.14.6で検証）
- Discord Bot トークン（[Discord Developer Portal](https://discord.com/developers/applications) で作成）
- Bot に付与する権限: チャンネル管理 / ロール管理 / ニックネーム管理 /
  メッセージ管理 / DM送信 / **メンバーをミュート**
- **特権インテント**: Server Members Intent と Message Content Intent を
  Developer Portal で有効化（役職DMの中継・メンバー管理に必要）
- サーバー側で、**Bot のロールをランクロールより上位**に置くこと

## セットアップ

```sh
# 1. Python 3.14 を確認し、.venv と依存を準備
./scripts/setup_venv.sh

# 2. 設定ファイルを作成（対象サーバーIDも固定することを推奨）
cp .env.example .env
# .env の DISCORD_TOKEN / DISCORD_GUILD_ID を編集
chmod 600 .env

# 3. 起動（多重起動防止と準備完了確認つき）
.venv/bin/python scripts/start_bot_detached.py

# 停止
./scripts/stop_bot.sh
```

個別サーバー専用の固定卓が必要な場合だけ、`.env.example`の
`WEREWOLF_LOCAL_ROOMS_JSON`を参考に`.env`へ追加してください。標準の常設卓は
13人クロストークの「総合」だけで、実運用ではローカル固定卓の「ねいとくん村」を
追加しています。それ以外はGMまたは仮GMが `GM/#村作成` から必要なときに名前村と
募集を同時作成します。13人ターン制は実装済みですが、利用者向けには未公開です。
ローカル卓の`room_id`と`name`は、導入後に
変更するとDBの復元対象やDiscordカテゴリが別卓扱いになるため変更しないでください。
`sync_permissions`は通常は省略時`true`です。このBotの「ねいとくん村」は
既存の手動構成を守るため省略時も`false`として扱います。他の卓で`false`にした場合も、カテゴリ・`#参加受付`・VCは
Discordで事前に作成して権限を手動設定し、Botは平常時の権限を同期しません。
Botに平常時の権限も自動同期させる卓だけ`true`を明示します。
ゲーム中の`#昼`・`#霊界`とVCの`speak`・`send_messages`は、秘密保持のためBotが管理します。
この2チャンネルはカテゴリの手動閲覧設定を引き継いでBotが作成し、VCの一時変更は
ゲーム終了時に開始前の値へ戻します。Bot所有IDを確認できない同名チャンネルは
手動作成物として削除せず、誤操作を避けるため起動またはゲーム開始を止めます。
設定値が壊れている場合は、一部だけ適用せずDiscord接続前に起動を中止します。

直接依存は `requirements.txt`、検証済みの推移依存を含む完全固定版は
`requirements-lock.txt` に記録しています。

Apple Siliconでは `/opt/homebrew/opt/python@3.14` をPATH探索より優先し、
Rosetta上のx86_64 Pythonは拒否します。稼働開始後にvenvを作り直す場合は、
必ず `./scripts/stop_bot.sh` でBotを停止してから `setup_venv.sh` を実行してください。
Bot稼働中または稼働状態を安全に確認できない場合、セットアップはvenvへ触れず中止します。

ログは `logs/bot.log`（5MB×3世代でローテーション）に出力されます。
起動時のスキーマ更新より前に`pre_migration`バックアップを作成し、作成できなければ
DBを変更せず起動を中止します。通常の起動時バックアップも別に保持します。
`DISCORD_GUILD_ID` を設定した場合、Botはその1サーバーだけを管理し、別サーバーへ
追加されてもゲーム状態を作成しません。直接 `bot.py` を起動した場合もランチャーと
同じプロセスロックを使うため、二重起動は拒否されます。

同梱AppleScriptは現在の実運用を誤って切り替えないよう、デスクトップ上の旧配置名
`bot`を先に、無い場合だけ`rank-werewolf-bot`を探します。`WEREWOLF_BOT_DIR`は
AppleScriptの実行環境へ明示的に渡した場合だけ最優先され、プロジェクトの`.env`からは
読まれません。Finderから実行する`.app`で任意配置を使う場合は、AppleScript内の探索先を
その絶対パスへ変更して再コンパイルしてください。

新規導入先に同名のDiscordカテゴリが既にある場合は、無関係なカテゴリを変更しないため
起動を中止します。そのカテゴリをこのBotの管理下へ引き継ぐと確認できた場合だけ、初回に
`.env`へ`ADOPT_EXISTING_LAYOUT=1`を設定してください。保存済みチャンネルIDがある既存運用は
この設定なしで従来の配置を再利用し、並び替えません。

> **効果音（任意）**: シーン切替のSEを鳴らすには `davey`、`PyNaCl`、`libopus` が
> 必要です。**discord.py 2.7系ではVoiceClientの接続にDAVE E2EE実装の `davey` が必須**で、
> 欠けると `davey library needed in order to use voice` になります。本プロジェクトは
> `discord.py[voice]==2.7.1`、`davey==0.1.6`、`PyNaCl==1.5.0` を固定しています。
> `setup_venv.sh` とBot起動時に、DAVEセッション生成・discord.py側の認識・libopusロードまで
> 検査します。`SE_ENABLED = True` のまま依存が不完全なら、無音で運用を続けず起動を停止します。
> macOS は `brew install opus`、Debian/Ubuntu は `apt install libopus0` を使用してください。
> Pythonとネイティブwheel/libopusのCPUアーキテクチャも一致している必要があります。
> libopusはプロジェクト同梱版をOSの自動探索より先にロードします。
> SEを使わない場合だけ `config.py` の `SE_ENABLED = False` へ変更してください。

音声依存だけを再確認する場合:

```sh
.venv/bin/python -m discord --version
.venv/bin/python -c 'import sounds; sounds.require_voice_ready()'
```

実際のDiscord VCへ接続して朝SEを1回鳴らす場合（BotがVCへ接続・再生・切断します）:

```sh
.venv/bin/python scripts/check_se_playback.py --scene morning
# 再生先を固定する場合
.venv/bin/python scripts/check_se_playback.py --scene morning --channel-id 123456789012345678
```

## カスタマイズ（土台として使う）

ルールやレギュレーションは主に **[config.py](config.py)** で変更できます。

| 変更したいもの | 定数 |
|---|---|
| 変種ごとの役職構成・人数・議論方式 | `VARIANT_DEFINITIONS`（`ROLE_DISTRIBUTION` / `MAX_PLAYERS` は従来13人クロストークの互換値） |
| 議論・夜・投票などの時間 | `VARIANT_DEFINITIONS[*].crosstalk_discussion_seconds` / `turn_round_seconds` / `NIGHT_*` / `VOTE_TIMEOUT` / `LAST_WILL_TIME` ほか |
| フェーズ間の猶予・ミュート整列 | `DISCUSSION_GRACE_TIME` / `MUTE_GRACE_TIME` / `MUTE_RETRY_DELAY` |
| レート計算 | `VARIANT_DEFINITIONS` の勝敗プール・狼予想枠・終盤判定 / `INITIAL_RATING` / `WIN_PARTICIPATION_BONUS` / `RATING_FLOOR` |
| 終了後推薦の受付時間 | `POSTGAME_RECOMMENDATION_TIMEOUT` |
| ランク段階・相対評価の割合 | `RANK_SPECS` / `SEASON_RANK_PERCENTAGES` / `SEASON_RANK_MIN_GAMES` |
| 統計の率・平均を表示する最低サンプル数 | `STATS_MIN_SAMPLES` |
| 募集の占有時間・通知・上限・同村拒否上限 | `VARIANT_DEFINITIONS[*].recruitment_occupancy_minutes` / `RECRUITMENT_*` / `PLAYER_BLOCK_LIMIT` |
| 不具合報告の投稿上限（1人あたり24時間） | `FEEDBACK_MAX_PER_DAY` |
| 標準卓の定義・参加条件 | `ROOM_DEFINITIONS` / 稼働中の卓は `ACTIVE_ROOM_DEFINITIONS` |
| 個別サーバー専用の固定卓・静的権限同期 | `.env`の`WEREWOLF_LOCAL_ROOMS_JSON` / `RoomDefinition.sync_permissions` |
| 名前村作成ハブの表示範囲 | `GM_INFO_ADMIN_ONLY` |
| 厳格ロール限定の固定卓 | `RoomDefinition.strict_access_role_names` |
| 名前村で公開するゲーム形式 | `USER_VISIBLE_VARIANT_IDS` |
| チャンネル/カテゴリ名 | `CH_*` / `VC_GAME` / `*_CATEGORY_NAME` |

進行ロジックそのものを変えたい場合は `room_runner.py`（1卓の進行）と
`views.py`（UI）が中心です。

## テスト

コードを変えたら、実際にDiscordへ繋がなくても挙動を検証できます。

```sh
# 4変種を最低1戦ずつ + 追加ゲームをシミュレート（同じ seed なら決定的）
.venv/bin/python simulate_games.py --runs 30

# 1変種だけを検証
.venv/bin/python simulate_games.py --variant v9_turn --runs 10

# 変種/ラダーを指定したレート分布の長期シミュレーション
.venv/bin/python simulate_games.py --mode population --variant v9_cross

# ユニットテスト
.venv/bin/python -m unittest discover -s tests

# コンパイル・依存整合・全ユニットテスト・ゲームシミュレーション
./scripts/run_checks.sh
```

シミュレータは必ず一時DBを作る `simulate_games.sandbox_db()` を通り、本番DBを
指したままなら停止します。レート検証では、ボーナス込みの総変動ではなく
固定プール本体の `elo_delta` が各試合でゼロサムになることを確認します。

## 構成

| ファイル | 役割 |
|---|---|
| `bot.py` | エントリーポイント |
| `command_sync.py` | スラッシュコマンドの差分同期とglobalコマンド監査 |
| `game.py` | GameCog（全卓管理・イベントdispatch・スラッシュコマンド） |
| `room_runner.py` | 1卓のゲーム進行ロジック |
| `permissions.py` | チャンネル権限管理 |
| `views.py` | ボタン/セレクトUI・ヘルプ・統計・フィードバック受付 |
| `recruitment.py` | 名前村一体型の募集・通知・同村拒否・運営UI |
| `database.py` | SQLite（ゲーム状態・統計・募集・フィードバック。`data/` 配下） |
| `rating.py` | レート計算・相対ランク |
| `config.py` | 定数・標準卓定義（**カスタマイズの入口**） |
| `models.py` | `Player` / `GameState` などのデータモデルと表示順ユーティリティ (`by_number`) |
| `room_config.py` | `.env`のローカル固定卓を厳格に検証して読み込む |
| `sounds.py` | シーン切替SEの生成・再生 |
| `simulate_games.py` | オフライン・シミュレータ |
