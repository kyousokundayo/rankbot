# ランク人狼Bot

13人/9人・クロストーク/ターン制・ボタンUI・レーティング付きの Discord 人狼ゲーム Bot です。
役職の配布から昼の議論・投票、夜の役職行動、シーズン制のレート/ランクまでを
すべて自動で進行します。

- 現在のバージョン: **v0.54**（`config.py` の `BOT_VERSION`、`SPEC.md` の対応Bot、`CHANGELOG.md` とここを更新時に揃える）
- 詳細仕様: **[SPEC.md](SPEC.md)**

## 主な機能

- **4変種を実装**: 13人クロストーク / 13人ターン / 9人クロストーク / 9人ターン（13人ターン制は実装済み・未公開）
- 13人配役は人狼3 / 狂人1 / 占い師1 / 霊媒師1 / 狩人1 / 村人6、9人配役は人狼2 / 狂人1 / 占い師1 / 霊媒師1 / 狩人1 / 村人3
- すべてボタン/セレクトUIで操作（スラッシュコマンドは管理用のみ）
- 夜の役職行動は `#昼` の常設パネル（[占い] [狩人] [霊媒]）から操作。襲撃は夜の間は変更可、占い・護衛は実行確認後に確定し変更不可。**狩人は護衛放棄不可**で、自分・前夜と同じ人は護衛できない
- 占い結果はエフェメラル表示で確認（占い師DM・初日白DM・霊能結果DM・人狼予想DMは廃止済み。DMはBotからの役職DMと各種通知だけ）
- ゲーム開始直後は時間切れでは進まず、**参加者全員が「役職を確認した」を押すと1日目へ進む**（一度押すと取り消せない）。狼の初日内通はこの役職確認と同時に始まる
- ゲーム開始時は、参加者全員（参加者を兼ねるGMを含む）がゲームVCへ接続済みであることを確認し、未接続者がいれば開始しない
- 議論中の仮投票は行わない。**クロストークの**通常投票は `#昼` の「投票参加」を押した順に、1人30秒（本人の発言終了でも可）ずつ発言する。発言終了SEと約2秒の切替後に候補を選び、確定するとその場で `A → C` と公開する。続く人がいれば投票開示SEと約2秒を挟んで次へ進む。候補選択は時間無制限で、通常のクロストーク投票には自動棄権がない（進行が詰まったときだけGMが締切）
- **ターン制の通常投票は一斉投票**（60秒、全員そろえば即開示）。規定の発言を終えてから投票に入る。決戦投票はどちらも一斉、決戦弁明はどちらも1人30秒で共通
- クロストークの議論時間は、13人村が初日8分・毎日1分短縮・下限3分、9人村が初日7分・毎日1分短縮・下限2分
- ターン制は初日50秒+80秒の2巡、2日目以降90秒の1巡。初日はランダム、以後は前夜の襲撃死者の次（護衛成功なら襲撃対象、どちらもなければランダム）から時計回りに話す。護衛成功時の開始席は公開情報だが、朝の文面は常に「平和な朝」のみ。本人のパスと村全体の30秒割り込み（13人は1日2回、9人は1回）に対応し、`#昼` は書き込み不可でVCだけを使う
- 役職確認タイムの開始と同時に、人狼がDMで挨拶できる能力使用なしの初日内通を始める。内通は最初の30秒、または全員確認・GM締切の早い方で終了する
- 夜は目安時間の終了後に初めて `#昼` へ「朝を迎える」を出し、**0/生存人数から押下ごとに公開更新**する。宣言は取消不可で、全員宣言かGMの「朝」で夜が明ける（未護衛の生存狩人がいる場合は強制不可）
- 人狼どうしのやり取りは**夜の制限時間で終了**（会話の中継も襲撃先の変更通知も止まる。襲撃先の選択自体は夜明けまで可能だが他の狼には伝わらない）
- 生存中の実人狼全員がDMで同意するとサレンダー成立。村陣営勝利として通常どおり戦績・レートに反映する
- 処刑・襲撃で死亡したプレイヤーは陣営を問わず `#昼` の[人狼予想]から予想を提出できる。実人狼も同じ画面を出せるが、正解を知るため採点対象外
- 投票と破壊的なGM操作は確認してから確定（誤操作防止）
- ゲーム中のGM状況・操作は `#昼` の末尾、受付操作は `#参加受付` の末尾に維持
- 常設卓はローカル固定卓（実運用では「ねいとくん村」）だけ。「総合」も含む旧常設卓はすべて廃止し、村はGMの名前村で作る。13人ターン制は引き続き未公開
- レート対象外の固定卓（`rated=false`。実運用では「ねいとくん村」）はレートを動かさず、統計・ランキング・最近の試合・卓セレクトのどこにも出ない。廃止した「総合」の過去の統計はそのまま残る
- `#統計` は既存の案内チャンネル `#総合` の直下に1つだけ配置（廃止した「総合」卓とは無関係。Botは作成も削除もしない）
- `#統計` の成績・履歴・勝率は稼働中の3変種で切り替え、レート順位は対応する13人/9人ラダーで表示（13人ターン制の履歴定義はDBに保持）
- ローカル固定卓は`.env`だけで追加可能。「ねいとくん村」はカテゴリ・`#参加受付`・VCの平常時権限をDiscordの手動設定のまま保持し、他のローカル卓は`sync_permissions=false`を明示した場合だけ同じ手動モードになる
- 名前村のカテゴリは `GM` カテゴリの直下（作成順に新しい村ほど上）に作る。既存カテゴリは並び替えない
- 起動時には既存チャンネル・カテゴリを並び替えず、保存済みIDと卓名から同じ構成を再利用
- `#統計` から不具合・分かりにくさ・改善要望を報告し、ゲーム状況とともにSQLiteへ保存
- GMまたは仮GM向けの `GM/#村作成` から名前村と募集を同時作成。募集カードはその村の `#参加受付` に置き、参加・取消・同村拒否確認・ゲーム開始を1か所で完結（独立した `#募集` は作らない）
- 名前村は 仮GM 1個 / GM 3個（設定運営ロール併用で7個）まで同時に持て、サーバー全体では12個まで。募集を複数同時に出せる一方、**ゲームを進行できるのは1人1村**。削除・改名は村が複数あるときセレクトで対象を選ぶ
- GM名前村は公開観戦型。カテゴリ・VC・`#昼`・`#霊界`を未参加者にも公開し、VCにも接続可能（生存参加者だけはゲーム中の`#霊界`を閲覧不可）。ゲーム中の観戦者は聞くだけで、VC発言とVC内チャットをBotが禁止し、参加者だけを進行に合わせて発言制御する
- 名前村の参加ボタンは参加意思・定員・ランク条件・同村拒否を管理するために使い、閲覧権限は変更しない。待機中の村にはGM以外も含めて複数登録でき、実際に進行できるゲームは1人1村だけ。参加取消後も観戦者としてVCやゲーム中チャンネルを利用できる
- 募集カードから**ルール・ヘルプ**を読める（受付が終わったカードからも読める）。主催者メニューでは備考・ゲーム形式・一括連絡に加えて**参加者を除外**でき、参加枠を外すと補欠が自動で繰り上がる
- ゲーム終了後は名前村でも**次村**で直前のメンバーを一括再登録できる（募集を作り直さずに連戦できる。同村拒否・DM開放・参加条件は通常の参加と同じ確認を通る）。主催画面の「前回設定で参加受付を再開」は、前回の設定だけを引き継いだ空の受付を新しく掲示し、参加者・補欠・通知履歴は持ち越さない
- 作成時と受付中に13人クロストーク / 9人クロストーク / 9人ターン制を選択・変更可能。定員、補欠、自動繰り上げ、参加者単位の15分前DMも選択中の形式へ追従
- 募集条件は「制限なし / 初心者 / 中級者 / 上級者」から簡単に選べ、必要な場合はランクを個別指定可能。初心者にはランク未設定者も含む
- `#参加受付` の `🔔通知` から通知設定を3項目で個別にON/OFF（「通知の許可」「村ができた時に通知」「この村を通知を受け取る」）
- 正常終了したGM名前村とレート対象のローカル固定卓のゲームを統計・ランキング・レート・ランクへ反映。13人村・9人クロストーク・9人ターン制は別ラダーで管理
- `#統計` の本人専用UIで最大50人の同村拒否を管理し、追加候補・登録済み一覧は25人ずつページ切替。既存の `開発/#運営` で被拒否数・9人均衡・受付中GM・募集を管理。Botは `開発` カテゴリも `#運営` も新規作成せず、欠落時は運営UI・通知だけを無効化してゲーム本体を継続。チャンネル閲覧者はDiscord上の手動権限設定で管理し、運営操作はAdministrator・所有者・設定運営ロール・設定運営ユーザー（`WEREWOLF_OPERATIONS_STAFF_USER_IDS`）に限定
- 再起動しても `#統計`・`GM/#村作成`・`#参加受付` の常設パネルは同じメッセージを編集して復元し、新着・通知を出さない（消えている場合だけ投稿し直す）
- 同村拒否の登録・上限到達と不具合報告は `開発/#運営記録` へ1件ずつ残し、`#運営` はボタンだけの操作盤にする。`#運営記録` が無い場合だけ `WEREWOLF_OPERATIONS_LOG_ROLES` のロールとBotだけが読める形でBotが作成（投稿はBotのみ）。ロール未設定・同名複数なら作らず、記録は `#運営` へ流す
- `#統計` の「自分の統計」から、本人だけに出る **レート推移グラフ**（全期間の折れ線PNG。シーズンリセット位置つき）と **相性**（同陣営／敵対それぞれについて「その相手がいる試合の勝率 − いない試合の勝率」を同じ陣営どうしで比較。共戦10戦以上が対象）を確認できる
- `#昼` の村パネルではCOに加え、占い・霊媒・狩人の結果を本人が公開できる。COと公開済み結果の一覧は夜時間から確認できる
- `#昼` の [占い] [狩人] [霊媒] は本人ならいつでも押せ、**初日（ランダム白）からの自分の記録**を表示。行動できるのは従来どおり夜だけ
- 占い結果DM・初日白DM・人狼予想DMを廃止（結果はいつでも `#昼` のボタンから見返せるため）。BotからのDMは役職DMと各種通知だけになった
- `開発/#運営` の **運営データ** で稼働（DAU/WAU/MAU・日別）・定着（新規流入・2戦目到達・週次継続率）・離脱（休眠・プレイ間隔・連続日数）・回転（募集成立率・試合時間）・通知（DM送達失敗率）・レート健全性（分布・月別増減）の6面を運営だけが確認できる
- `#統計` の「全体データ」で卓別の勝敗・日数・平和・処刑・初夜噛み・生存狼推移・時間帯・GMを表示。プレイヤー指標は試合時の相対ランク別に切替
- 占い・護衛・死亡日/死因・試合時ランク・GMを導入後の各試合へ保存し、個人統計にシーズン役職勝率・連勝/連敗・初夜襲撃・推薦数を追加
- サーバーミュートによる自動発言制御（昼/夜/投票/弁明/遺言）。参加者を兼ねるGMはプレイヤーとしてミュート対象になり、専任GMだけを自動制御から除外する
- 13人村 `l13` / 9人クロストーク `l9_cross` / 9人ターン制 `l9_turn` の3ラダー。変種別固定プール + 卓帯補正 + 活躍ボーナス + エメラルドを含む相対ランク9段階 + 共通シーズン境界
- 終了後、霊媒師・初日処刑者・初夜襲撃死者が匿名で参加者へレート+1を贈る推薦
- 終了時に**全役職の行動・投票・死亡を発生順にまとめた進行ログ**を `#昼` へ掲示（拒否された操作も残るため二重実行の有無をその場で確認できる）
- ローカル固定卓（手動権限卓を含む）・GM名前村で終了した `#昼` は、すべて**公開ログカテゴリへ試合番号付きで退避**（`04-昼`。書き込み不可・最大50試合ぶんで、上限に達すると古い順に40試合ぶんまで整理）。`#霊界` はログに残さず削除する
- Bot再起動をまたいでゲームを途中再開（状態をSQLiteへ常時保存）。終了・リセット・除外でも受付と主催パネルを復旧し、番号付きニックネームの復元に失敗した場合は再試行できる状態を保持
- シーン切替の効果音（任意・後述の音声ライブラリが必要）

## 動作要件

- Python 3.14（3.14.6で検証）
- Discord Bot トークン（[Discord Developer Portal](https://discord.com/developers/applications) で作成）
- Bot に付与する権限: チャンネル管理 / ロール管理 / ニックネーム管理 /
  メッセージ管理 / DM送信 / **メンバーをミュート**
- **特権インテント**: Server Members Intent と Message Content Intent を
  Developer Portal で有効化（役職DMの中継・メンバー管理に必要）
- サーバー側で、**Bot のロールをランクロールより上位**に置くこと

## セットアップ

```sh
# 1. Python 3.14 を確認し、.venv と依存を準備
./scripts/setup_venv.sh

# 2. 設定ファイルを作成（対象サーバーIDも固定することを推奨）
cp .env.example .env
# .env の DISCORD_TOKEN / DISCORD_GUILD_ID を編集
chmod 600 .env

# 3. 起動（多重起動防止と準備完了確認つき）
.venv/bin/python scripts/start_bot_detached.py

# 停止
./scripts/stop_bot.sh
```

個別サーバー専用の固定卓が必要な場合だけ、`.env.example`の
`WEREWOLF_LOCAL_ROOMS_JSON`を参考に`.env`へ追加してください。標準の常設卓は
ありません。実運用ではローカル固定卓の「ねいとくん村」だけを
追加しています。それ以外はGMまたは仮GMが `GM/#村作成` から必要なときに名前村と
募集を同時作成します。13人ターン制は実装済みですが、利用者向けには未公開です。
ローカル卓の`room_id`と`name`は、導入後に
変更するとDBの復元対象やDiscordカテゴリが別卓扱いになるため変更しないでください。
`sync_permissions`は通常は省略時`true`です。このBotの「ねいとくん村」は
既存の手動構成を守るため省略時も`false`として扱います。他の卓で`false`にした場合も、カテゴリ・`#参加受付`・VCは
Discordで事前に作成して権限を手動設定し、Botは平常時の権限を同期しません。
Botに平常時の権限も自動同期させる卓だけ`true`を明示します。
ゲーム中の`#昼`・`#霊界`とVCの`speak`・`send_messages`は秘密保持のためBotが一時管理し、
終了時に開始前の値へ戻します（安全停止の条件は [SPEC.md](SPEC.md) の4章を参照）。
設定値が壊れている場合は、一部だけ適用せずDiscord接続前に起動を中止します。

直接依存は `requirements.txt`、検証済みの推移依存を含む完全固定版は
`requirements-lock.txt` に記録しています。

Apple Siliconでは `/opt/homebrew/opt/python@3.14` をPATH探索より優先し、
Rosetta上のx86_64 Pythonは拒否します。稼働開始後にvenvを作り直す場合は、
必ず `./scripts/stop_bot.sh` でBotを停止してから `setup_venv.sh` を実行してください。
Bot稼働中または稼働状態を安全に確認できない場合、セットアップはvenvへ触れず中止します。

ログは `logs/bot.log`（5MB×3世代でローテーション）に出力されます。
既存DBは起動時にスキーマと整合性を検証し、未移行または不整合なら変更せず起動を中止します
（検証項目は [SPEC.md](SPEC.md) の11章を参照）。旧版DBからの直接アップグレードはサポートしないため、
v0.40へ移行済みのバックアップまたは新規DBを使用してください。移行済みDBに残る未使用の旧列・
空テーブルは現行コードから参照せず、起動時にも自動削除しません。
稼働中は24時間ごとのバックアップとシーズンリセット前バックアップを保持します。
v0.47のGM村複数化にあわせて、旧DBに残る `private_rooms` の1人1村制約は起動時に
テーブル再構築で外します（村名の一意制約は維持し、旧版が残したnullableな余分列も
引き継ぎます）。この移行は、本番DBと復旧対象にする旧バックアップの両方で制約解除を
確認できるまでは削除しません。

シーズン1を1試合目から始めるためのプレシーズン一括削除は
`scripts/purge_preseason_stats.py` にあります。既定は削除件数を表示するだけで、
`--execute --confirm-season1 ERASE-PRESEASON` をそろえたときだけ、自動バックアップを
作成し、`integrity_check`・対象テーブルの`foreign_key_check`・対象件数の一致を
確認してから消します
（`--reset-ratings` でレート・シーズン履歴も白紙化）。**試合番号が1から振り直しに
なる**ため、Discord側のログカテゴリも運営が手で削除する前提です。Botは停止してから
実行してください。`--execute` はBot本体と同じロックを取得できない場合、安全のため
削除を開始せず中止します。

`DISCORD_GUILD_ID` を設定した場合、Botはその1サーバーだけを管理し、別サーバーへ
追加されてもゲーム状態を作成しません。直接 `bot.py` を起動した場合もランチャーと
同じプロセスロックを使うため、二重起動は拒否されます。

同梱AppleScriptは現在の実運用を誤って切り替えないよう、デスクトップ上の旧配置名
`bot`を先に、無い場合だけ`rank-werewolf-bot`を探します。`WEREWOLF_BOT_DIR`は
AppleScriptの実行環境へ明示的に渡した場合だけ最優先され、プロジェクトの`.env`からは
読まれません。Finderから実行する`.app`で任意配置を使う場合は、AppleScript内の探索先を
その絶対パスへ変更して再コンパイルしてください。

新規導入先に同名のDiscordカテゴリが既にある場合は、無関係なカテゴリを変更しないため
起動を中止します。そのカテゴリをこのBotの管理下へ引き継ぐと確認できた場合だけ、初回に
`.env`へ`ADOPT_EXISTING_LAYOUT=1`を設定してください。保存済みチャンネルIDがある既存運用は
この設定なしで従来の配置を再利用し、並び替えません。

> **効果音（任意）**: シーン切替のSEを鳴らすには `davey`、`PyNaCl`、`libopus` が必要です
> （必須になった理由と起動停止の仕様は [SPEC.md](SPEC.md) の5章を参照）。本プロジェクトは
> `discord.py[voice]==2.7.1`、`davey==0.1.6`、`PyNaCl==1.5.0` を固定し、
> `setup_venv.sh` とBot起動時に依存を検査します。
> macOSで `brew install opus` を実行してください。
> Pythonとネイティブwheel/libopusのCPUアーキテクチャも一致している必要があります。
> `data/lib/libopus.dylib` がある場合はその同梱版をHomebrewより先にロードします。
> SEを使わない場合だけ `config.py` の `SE_ENABLED = False` へ変更してください。

> **戦績カード画像（任意）**: `/統計` の「画像で見る」で使う日本語対応PNGの
> 描画には `Pillow` と、日本語グリフを持つフォントが必要です。フォントは
> 環境変数 `WEREWOLF_STATS_CARD_FONT_PATH`（1ファイルを直接指定）→
> `assets/fonts/*.ttf|otf|ttc`（同梱していれば）→ OS標準フォントの順で
> 探し、どれも無ければ**この機能だけを自動的に無効化**します（Botは落ちません）。
> **追加インストールは不要です**。ヒラギノ角ゴシックなどのmacOS標準搭載
> フォントをそのまま使います（`/System/Library/Fonts/ヒラギノ角ゴシック W3.ttc`
> を自動で拾います）。フォントが見つからない環境ではボタン自体が表示されません
> （`stats_image.font_available()` で判定）。
>
> シーズン末に全員分の戦績カード画像をまとめて生成する場合
> （**DMでの自動配布はしません**。配布は運営が手動で判断してください）:
> ```sh
> .venv/bin/python scripts/generate_season_cards.py --output-dir ./season_cards
> ```

音声依存だけを再確認する場合:

```sh
.venv/bin/python -m discord --version
.venv/bin/python -c 'import sounds; sounds.require_voice_ready()'
```

実際のDiscord VCへ接続して朝SEを1回鳴らす場合（BotがVCへ接続・再生・切断します）。
通常チェックでは実行せず、実Discordでの再生確認を明示的に行うときだけ使用します:

```sh
.venv/bin/python scripts/check_se_playback.py --scene morning
# 再生先を固定する場合
.venv/bin/python scripts/check_se_playback.py --scene morning --channel-id 123456789012345678
```

## カスタマイズ（土台として使う）

ルールやレギュレーションは主に **[config.py](config.py)** で変更できます。

| 変更したいもの | 定数 |
|---|---|
| 変種ごとの役職構成・人数・議論方式 | `VARIANT_DEFINITIONS`（`MAX_PLAYERS` は従来13人クロストークの互換値） |
| 議論・夜・投票などの時間 | `VARIANT_DEFINITIONS[*].crosstalk_discussion_seconds` / `turn_round_seconds` / `NIGHT_*` / `VOTE_TIMEOUT` / `LAST_WILL_TIME` ほか |
| フェーズ間の猶予・ミュート整列 | `DISCUSSION_GRACE_TIME` / `MUTE_GRACE_TIME` / `MUTE_RETRY_DELAY` |
| レート計算 | `VARIANT_DEFINITIONS` の勝敗プール・狼予想枠・終盤判定 / `INITIAL_RATING` / `WIN_PARTICIPATION_BONUS` / `RATING_FLOOR` |
| 終了後推薦の受付時間 | `POSTGAME_RECOMMENDATION_TIMEOUT` |
| ランク段階・相対評価の割合 | `RANK_SPECS` / `SEASON_RANK_PERCENTAGES` / `SEASON_RANK_MIN_GAMES` |
| 統計の率・平均を表示する最低サンプル数 | `STATS_MIN_SAMPLES` |
| 募集の占有時間・通知・上限・同村拒否上限 | `VARIANT_DEFINITIONS[*].recruitment_occupancy_minutes` / `RECRUITMENT_*` / `PLAYER_BLOCK_LIMIT` |
| 不具合報告の投稿上限（1人あたり24時間） | `FEEDBACK_MAX_PER_DAY` |
| 標準卓の定義・参加条件 | `ROOM_DEFINITIONS` / 稼働中の卓は `ACTIVE_ROOM_DEFINITIONS` |
| 個別サーバー専用の固定卓・静的権限同期 | `.env`の`WEREWOLF_LOCAL_ROOMS_JSON` / `RoomDefinition.sync_permissions` |
| 名前村作成ハブの表示範囲 | `GM_INFO_ADMIN_ONLY` |
| 厳格ロール限定の固定卓 | `RoomDefinition.strict_access_role_names` |
| 名前村で公開するゲーム形式 | `USER_VISIBLE_VARIANT_IDS` |
| チャンネル/カテゴリ名 | `CH_*` / `VC_GAME` / `*_CATEGORY_NAME` |

進行ロジックそのものを変えたい場合は `room_runner.py`（1卓の進行）と
`views.py`（UI）が中心です。

## テスト

コードを変えたら、実際にDiscordへ繋がずユニットテストで確認できます。

```sh
# ユニットテスト
.venv/bin/python -m unittest discover -s tests

# コミット前の完全確認
./scripts/run_checks.sh
```

ゲームシミュレーションは通常チェック・CI・リリース作業では実行しません。
ユーザーから明示的に依頼された場合だけ実行します。

## 構成

| ファイル | 役割 |
|---|---|
| `bot.py` | エントリーポイント |
| `command_sync.py` | スラッシュコマンドの差分同期とglobalコマンド監査 |
| `game.py` | GameCog（全卓管理・イベントdispatch・スラッシュコマンド） |
| `room_runner.py` | 1卓のゲーム進行ロジック |
| `permissions.py` | チャンネル権限管理 |
| `views.py` | ボタン/セレクトUI・ヘルプ・統計・フィードバック受付 |
| `recruitment.py` | 名前村一体型の募集・通知・同村拒否・運営UI |
| `database.py` | SQLite（ゲーム状態・統計・募集・フィードバック。`data/` 配下） |
| `rating.py` | レート計算・相対ランク |
| `config.py` | 定数・標準卓定義（**カスタマイズの入口**） |
| `models.py` | `Player` / `GameState` などのデータモデルと表示順ユーティリティ (`by_number`) |
| `room_config.py` | `.env`のローカル固定卓を厳格に検証して読み込む |
| `sounds.py` | シーン切替SEの生成・再生 |
| `stats_image.py` | 戦績カード画像 (PNG) の描画。Discord非依存の純関数 |
